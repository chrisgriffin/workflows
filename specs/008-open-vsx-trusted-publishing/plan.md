# Plan: Publish to Open VSX with trusted publishing

## Technical context

- ovsx 1.3.0, already pinned, has `--trusted-publishing`: it reads `ACTIONS_ID_TOKEN_REQUEST_URL`/`_TOKEN` (`lib/oidc.js`), exchanges the ID token at `/api/-/trusted-publishing/token`, and lets `OVSX_PAT` win when both are present.
- The runner sets `ACTIONS_ID_TOKEN_REQUEST_URL` only when the job's token has `id-token: write`. This file has no `permissions:` key, so the caller's grant reaches the job unchanged.
- Open VSX matches the registration on the token's `workflow_ref` claim (the caller's stub file), not `job_workflow_ref`, so a stub calling this workflow registers under its own filename.

## Design

1. In the publish step, the early "nothing to publish" exit also requires no ID-token source.
2. The Open VSX branch: token → as today; else ID-token source → `--trusted-publishing`; else the notice, now naming both.
3. Tests: `runStep` takes an `oidc` flag that sets `ACTIONS_ID_TOKEN_REQUEST_URL`; cases for trusted publishing, token precedence, and the notices.
4. README: the switch, under the `OVSX_PAT` bullet.

## Surfaces touched

- a `_reusable-*.yml` body (`_reusable-create-github-release.yml`): no input, secret or `permissions:` change, so no caller's ceiling moves. token-atlas, the one caller passing `marketplace_packages`, grants `id-token: write` in its own PR.
- a workflow job name that is a required check: none renamed.
- a published surface: README § `_reusable-create-github-release.yml`; CHANGELOG is generated by the release PR.
