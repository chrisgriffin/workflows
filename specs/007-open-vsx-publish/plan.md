# Plan: Publish VS Code extensions to Open VSX on release

## Technical context

- #17 moved the publish into the `marketplace` job: `needs: release`, not gated on the release's skip, downloading the Release's assets by version.
- `ovsx` 1.3.0 (current) reads its token from `OVSX_PAT` (`lib/util.js`), its `--skip-duplicate` swallows "is already published.", and `--packagePath` takes several files.
- A stub that passes a secret the called workflow does not declare fails, so token-atlas passes `OVSX_PAT` only after the release that moves `v1`.

## Design

1. Declare `OVSX_PAT` beside `VSCE_PAT`.
2. The publish step: one notice and exit when neither token exists; else download, then per registry a notice or the pinned tool (`env -u` the other token) with `--skip-duplicate --packagePath $PACKAGES`, appending to `FAILED` on failure; `::error::` and `exit 1` at the end if `FAILED` is set.
3. Tests stub `gh` and `npx` (per-tool exit codes, logging the tokens each saw).

## Surfaces touched

- a `_reusable-*.yml` body (`_reusable-create-github-release.yml`): a new optional secret, no input or `permissions:` change. token-atlas passes it in its own PR, which merges after the release that moves `v1`; other callers publish nothing and are unaffected.
- a workflow job name that is a required check: none renamed.
- a published surface: README § `_reusable-create-github-release.yml`; CHANGELOG is generated by the release PR.
