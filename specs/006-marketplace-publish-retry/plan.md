# Plan: Let a re-run retry a failed Marketplace publish

## Technical context

- The publish step sat after `gh release create` with `if: steps.version.outputs.skip != 'true'`; `skip` is true whenever `v$VERSION` already has a Release, which a failed publish leaves behind.
- `vsce` 3.9.2 (the pinned version) has `--skip-duplicate`: a version already on the Marketplace logs "already published" and returns instead of throwing.
- The release job's `gh release create` attaches `release_assets`; token-atlas attaches and publishes the same `./*.vsix`, so the Release holds the file to publish.

## Design

1. Release job gains `outputs.version`; the Marketplace step leaves it.
2. New `marketplace` job: `needs: release`, `if: inputs.marketplace_packages != ''`, no skip gate, no `permissions:` (the caller's `contents: write` covers the download). Steps: `setup-node`, then the publish script: the no-PAT notice, `gh release download "v$VERSION"` into a temp dir, `vsce publish --skip-duplicate --packagePath $PACKAGES` there.
3. Tests run the step's script with `gh` and `npx` stubbed.

## Surfaces touched

- a `_reusable-*.yml` body (`_reusable-create-github-release.yml`): no input, secret or `permissions:` change, so no calling stub changes; every caller picks it up when the floating `v1` tag moves with the next release.
- a workflow job name that is a required check: none renamed (a new `marketplace` job, not required anywhere).
- a published surface: README § `_reusable-create-github-release.yml` and § Tests; CHANGELOG is generated by the release PR.
